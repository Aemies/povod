# Повод — статическая версия (GitHub Pages)

Помощник клиентского менеджера: название компании + сайт/ИНН/регион → факты из открытых источников со ссылками → гипотезы, вопросы, начало разговора → оценка полезности.

Версия 0.3 работает без своего сервера и базы. Сайт — это набор статических файлов, его можно бесплатно разместить на GitHub Pages. Ключи API вводит сам менеджер или выдаёт руководитель.

## Как устроено

```
Браузер КМ ──► OpenAI (напрямую, если OpenAI доступен из сети КМ)
           ──► Другой OpenAI-совместимый API (напрямую, если он разрешает запросы из браузера)
           ──► Прокси руководителя ──► GigaChat (OAuth + чат)
                                  └──► Yandex Search API (поиск) + текст первых страниц
```

* **GigaChat нельзя вызвать из браузера напрямую**: у него нет CORS, а сертификат Минцифры не входит в доверенные браузера. Поэтому нужен маленький прокси (папка `proxy/`). Он бесплатно запускается в Яндекс Облаке.
* Прокси пересылает запросы только на 3 фиксированных адреса GigaChat, а поиск выполняет сам через Yandex Search API от имени сервисного аккаунта функции. Отдельный ключ поиска не нужен.
* Поиск и общий ключ GigaChat доступны только по **коду доступа** руководителя. КМ вводит код; при желании — свой ключ GigaChat вместо общего.
* История карточек, оценки и ключи хранятся **только в браузере** КМ (localStorage). Оценки КМ выгружает в CSV кнопкой в разделе «Мои карточки».

## Файлы

| Файл | Что внутри |
| --- | --- |
| `index.html`, `styles.css`, `extra.css`, `favicon.svg` | Страница и оформление |
| `js/app.js` | Интерфейс |
| `js/providers.js` | Подключения к GigaChat, OpenAI и другим API |
| `js/report.js` | Промпт, проверка ответа модели, экспорт карточки |
| `js/storage.js` | Хранение настроек, истории и ссылки-настройки |
| `proxy/index.js` | Прокси для Яндекс Облака (точка входа `index.handler`) |
| `proxy/server.js` | Тот же прокси как обычный Node-сервер, для проверки |

## Шаг 1. Разместить сайт на GitHub Pages (≈10 минут)

1. Зайдите на github.com → **New repository**. Имя, например, `povod`. Видимость **Public**: бесплатный GitHub Pages работает только с публичными репозиториями. В коде нет ключей, поэтому это безопасно.
2. На странице нового репозитория: **Add file → Upload files**, перетащите **содержимое** этой папки (не саму папку) и нажмите **Commit changes**.
   Если папка `.nojekyll` не загрузилась через браузер, ничего страшного.
3. **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main**, папка **/(root)** → **Save**.
4. Через 1–2 минуты сайт будет по адресу `https://<ваш-логин>.github.io/povod/`.

С OpenAI сайт уже работает: Подключение → OpenAI → ключ. OpenAI не принимает запросы с российских IP, поэтому для КМ в России нужен GigaChat через прокси.

## Шаг 2. Прокси для GigaChat в Яндекс Облаке (делает руководитель, ≈20 минут)

Что нужно заранее:
* **Authorization key GigaChat** — в [GigaChat Studio](https://developers.sber.ru/studio) создайте проект GigaChat API и возьмите «Ключ авторизации». Для юрлица тип B2B или CORP, для физлица PERS.
* **Сертификат Минцифры** — на [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt) скачайте корневой сертификат для Linux/PEM (`russian_trusted_root_ca_pem.crt`) и переименуйте в `russian_trusted_root_ca.pem`.

Шаги:
1. Откройте [console.yandex.cloud](https://console.yandex.cloud), создайте платёжный аккаунт (нужна карта; у Cloud Functions есть бесплатный объём вызовов в месяц, для пилота его хватает с запасом — проверьте актуальные условия на сайте).
2. **Сервисные аккаунты → Создать**: имя `povod-proxy-sa`, роль `search-api.webSearch.user` (поиск Яндекса тарифицируется за запросы — проверьте цены в разделе Search API).
3. **Cloud Functions → Создать функцию**, имя `povod-proxy`. В обзоре функции включите **Публичная функция**.
4. **Редактор**: среда выполнения **Node.js 22**, способ — **Редактор кода**. Создайте файлы:
   * `index.js` — содержимое `proxy/index.js`;
   * `russian_trusted_root_ca.pem` — содержимое скачанного сертификата.
5. Параметры: точка входа `index.handler`, таймаут **180 секунд**, память **128 МБ**, сервисный аккаунт `povod-proxy-sa`.
6. Переменные окружения:

   | Переменная | Значение |
   | --- | --- |
   | `ALLOWED_ORIGIN` | `https://<ваш-логин>.github.io` (без `/povod` и без слэша в конце) |
   | `ACCESS_CODE` | длинный код для команды, например 4 случайных слова через дефис |
   | `GIGACHAT_AUTH_KEY` | Authorization key GigaChat (без слова Basic) |
   | `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` |
   | `FOLDER_ID` | ID каталога Яндекс Облака (виден в консоли рядом с именем каталога) |

   `GIGACHAT_AUTH_KEY` необязателен: без него каждый КМ вводит свой ключ GigaChat. Без `ACCESS_CODE` поиск и общий ключ не работают.
7. **Сохранить изменения** (создастся версия). Ссылка функции имеет вид `https://functions.yandexcloud.net/<id>`.
8. Откройте эту ссылку в браузере. Должно быть `{"ok":true,…,"search":true,"caLoaded":true}`. Если `caLoaded:false`, файл сертификата не найден.

Прокси можно запустить и на любом сервере с Node.js 22: `node proxy/server.js` (порт 8787) за HTTPS, переменные те же.

## Шаг 3. Настроить сайт и раздать команде

1. Руководитель открывает сайт → **Подключение → GigaChat**, вводит адрес прокси и код, жмёт **Проверить подключение**, затем **Сохранить**.
2. Кнопка **Ссылка-настройка для команды** копирует ссылку, в которой зашиты адрес прокси и модель (ключей и кода в ней нет).
3. Ссылку разослать КМ, **код доступа — отдельно и лично**.
4. КМ открывает ссылку, вводит код, жмёт «Сохранить» и работает.
5. Раз в неделю КМ жмёт «Мои карточки → Выгрузить оценки (CSV)» и отправляет файл организатору.

Сменить код = поменять `ACCESS_CODE` в функции и создать новую версию. Старый код перестаёт работать сразу.

## Проверка на своём компьютере

```bash
cd povod-static
python3 -m http.server 4173        # сайт: http://localhost:4173
ALLOWED_ORIGIN=http://localhost:4173 ACCESS_CODE=test node proxy/server.js   # прокси: http://localhost:8787
```

Для GigaChat положите `russian_trusted_root_ca.pem` в `proxy/`.

## Ограничения

* Сквозной сценарий с настоящими GigaChat и Yandex Search API ещё не проверялся. Логику проверяли на подставных ответах.
* История и оценки живут в одном браузере. Другой браузер или очистка данных сайта — пустая история.
* Код доступа общий на группу. Защита от подбора (10 попыток за 15 минут) работает в пределах одного экземпляра функции, поэтому код должен быть длинным.
* Запрос о компании уходит в выбранный ИИ и в поиск Яндекса. Банковские и персональные данные вводить нельзя.
